# 串口联调说明（上位机 ↔ 下位机）

## 一、三个词，一句话讲清

| 词 | 是什么 | 在我们车上 |
| --- | --- | --- |
| **上位机** | 干"费脑子"的活：看图、认棋子、做决策 | 车上的 RDK X5 / 树莓派，跑 Python |
| **下位机** | 干"要准时"的活：每 1 毫秒读一次编码器、算 PID、出 PWM | STM32F407 |
| **串口** | 两台机器之间的一根"电话线"：按字节收发的数据线 | USB 转 TTL 模块，或板子上的 UART 引脚 |

为什么要拆成两个：Python 算一帧要 20~30ms，还可能被系统调度打断；
而电机控制必须**每 1ms 严格准时**。所以"动脑子"和"管手脚"分开，
中间用串口传"我该去哪、走多远"这种**高层指令**（每秒几十条就够）。

## 二、接线（4 根线）

```
上位机（USB）── USB 转 TTL 模块 ──┬── TX  →  STM32 的 RX (PA3/USART2_RX)
                                  ├── RX  ←  STM32 的 TX (PA2/USART2_TX)
                                  └── GND ── GND（必须共地！）
STM32 供电单独走电池，不要从 USB 取电驱动电机
```

三条铁律：

1. **TX 接对方的 RX**（不是 TX 接 TX）；
2. **必须共地**，否则一定乱码；
3. TTL 电平是 **3.3V**，别把 5V 信号直接灌进 STM32 的 RX。

参数：**115200，8 数据位，无校验，1 停止位**（8N1）。

## 三、线上跑的数据长什么样

上位机 → 下位机（一条指令一行，末尾 `*XX` 是校验）：

```
$GOTO,1200,800,180*3A      去 (1200,800)mm，车头摆到 180°
$TURN,-90*5C               原地转到 -90°
$DRIVE,1380*7F             沿当前朝向直走 1380mm（负数倒车）
$BLADE,1*2D                放下推板（0=抬起）
$STOP*3F                   立即停
```

下位机 → 上位机（每秒 25 条心跳）：

```
$P,1200,800,90,1*4B        位姿 x,y,朝向, 当前指令是否完成
```

校验算法：`$` 和 `*` 之间所有字符的 ASCII 求和，取低 8 位，两位十六进制。
Python 端 `Command.encode()` 和 C 端 `protocol.c` 的实现**已逐条比对过，完全一致**。

## 四、上车五步（别跳步）

| 步骤 | 做什么 | 通过标准 |
| --- | --- | --- |
| 1 | 架空车，手动发 `$DRIVE,300*..` | 两只轮子都往前转（反了改 `MOTOR_*_SIGN`） |
| 2 | 手推车走 1m | 上位机显示的 x 变化 ≈1000mm（差太多改轮径/线数/倍频） |
| 3 | 发 `$TURN,90*..` | 车顺时针转 90°，回传 h≈90 |
| 4 | 电脑发 `$STOP*..` | 1 秒内停车，且 `$P` 心跳持续不断 |
| 5 | 跑 `run_live.py`（先 `--no-serial`，再真串口） | 看日志里状态能走完 `APPROACH→PUSH→RETREAT` |

## 五、怎么跑（三种模式，从安全到真车）

```powershell
# ① 只跑视觉+决策，不发指令（最安全，先确认程序不崩）
python strategy/run_live.py --camera 0 --no-serial

# ② 回放录像/图片，调参用（不需要车）
python strategy/run_live.py --source vision/data/raw/demo.mp4 --no-serial --pose 1500 1000 180

# ③ 真车
python strategy/run_live.py --camera 0 --port COM7
```

按键：**空格**开始/暂停（比赛开始就按一下）、`s` 存一张标注图、`q` 退出。

### 安全机制（已内置）

- 串口超过 **0.5 秒**没心跳 → **冻结决策**并持续发 `$STOP`，日志里状态显示 `LINK_LOST`；
- 暂停、退出、异常时都会补发 `$STOP`；
- 同一条指令不会重复发（避免把"走到一半"的任务重置）。

## 六、跑出来的数据在哪、怎么看

每次运行都会生成：

```
logs/live_20261017_174526.jsonl          每帧一行（含状态、指令、位姿、耗时、得分）
logs/live_20261017_174526.summary.txt    report_log.py 生成的人话报告
vision/data/raw/live_*.mp4               如果加了 --save-video
```

看报告：

```powershell
python strategy/report_log.py logs/live_20261017_174526.jsonl
```

输出示例：

```

趟数 4，脱困 1，最终视野累计得分 176
状态分布：SEARCH 1200  PUSH 300  APPROACH 500 ...

串口心跳：最大间隔 0.08s，超过 0.5s 的次数 0
可疑点：未发现明显异常
```

## 八、常见问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 找不到 COM 口 | USB 转 TTL 没装驱动 | 设备管理器看"端口(COM 和 LPT)"；CH340/CP2102 装对应驱动 |
| `PermissionError` / 打不开串口 | 串口助手还开着 | 关掉串口助手/另一个终端里的脚本 |
| 一打开就一堆乱码 | 波特率不对 / 没共地 / TXRX 接反 | 检查 115200、共地、TX→RX |
| `LINK_LOST` 一直出现 | 下位机没发心跳 / 程序卡死 | 先用串口助手看有没有 `$P,...` 每秒 25 条 |
| 车不走，日志里指令在变 | 下位机没执行（PWM/使能/驱动） | 回到"四、上车五步"第 1 步 |
| 位姿一直是 0 | 编码器没接 / 中断没进 | 手转轮子看计数变不变 |
