# firmware · STM32 执行层

> ⚠ **状态：骨架，未编译、未上板验证。** 机器上没有 ARM 编译器，
> 这份代码按"能直接并进 CubeMX 工程"来写，但引脚、定时器、方向符号必须按你们的板子改。
> 把它当成"填空模板 + 调试清单"，不要当成能直接烧的固件。

## 分工

```
上位机（Python, vision/ + strategy/）        下位机（本目录）
  看：识别棋子、算坐标                         听：解析 $GOTO/$TURN/$DRIVE/$BLADE/$STOP
  想：选目标、规划走法                          走：差速运动学 + 轮速 PI
  说：发运动指令                              报：$P,x,y,h,done 回传位姿
```

这样分工的原因：视觉和决策要频繁改、要调参，放在电脑上用 Python 最快；
而 1kHz 的速度环和编码器里程计必须实时，放在 STM32 上。

## 文件

| 文件 | 作用 |
| --- | --- |
| `config.h` | **所有要按实物改的参数**：轮径、轮距、编码器线数、减速比、PID、方向符号 |
| `chassis.h/.c` | 差速底盘：里程计、轮速 PI、`GOTO/TURN/DRIVE/BLADE` 四个动作的执行 |
| `protocol.h/.c` | 串口协议：收帧校验 + 指令分发 + 位姿回传（不依赖 printf） |
| `app_main.c` | 主程序骨架 + 硬件钩子（`hw_read_encoder` / `hw_set_pwm` / `hw_set_blade`） |

## 串口协议（115200 8N1）

上位机 → 下位机：

| 指令 | 含义 | 例子 |
| --- | --- | --- |
| `$GOTO,x,y,h*XX` | 去 (x,y) mm 并摆正到 h 度（h：0=+x，顺时针为正） | `$GOTO,1200,800,180*3A` |
| `$TURN,h*XX` | 原地转到 h 度 | `$TURN,-90*5C` |
| `$DRIVE,d*XX` | 沿当前朝向直走 d mm（负数倒车） | `$DRIVE,1380*7F` |
| `$BLADE,0\|1*XX` | 推板抬起 / 放下 | `$BLADE,1*2D` |
| `$STOP*XX` | 立即停 | `$STOP*3F` |
| `$IDLE*XX` | 没有任务（保持） | `$IDLE*1C` |

下位机 → 上位机（25Hz）：

| 指令 | 含义 |
| --- | --- |
| `$P,x,y,h,done*XX` | 位姿（mm/度）+ 当前指令是否完成（0/1） |
| `$BOOT,OK*XX` | 上电就绪 |
| `$ERR,CRC*XX` / `$ERR,VERB*XX` | 校验错 / 未知指令 |

校验 `XX` = `$` 和 `*` 之间所有字节求和取低 8 位（和 Python 端 `command.encode()` 一致）。

## 上电调试顺序（**别跳步**）

| 步骤 | 做什么 | 验收标准 | 不对就改 |
| --- | --- | --- | --- |
| 1 | 架空车，发 `$GOTO,1000,0,0`（或 `$DRIVE,300`） | 两只轮子**都往前**转 | `MOTOR_L_SIGN` / `MOTOR_R_SIGN` 取反 |
| 2 | 用手推车直线 1m | 回传的 x 变化 ≈1000mm（误差 <5%） | `WHEEL_DIA_MM`、`ENCODER_PPR`、`GEAR_RATIO`、`ENC_MULT` |
| 3 | 发 `$TURN,90` | 车原地顺时针转 90°，回传 h≈90 | 方向反了改 `ENC_*_SIGN`；转的不是 90° 改 `TRACK_MM` |
| 4 | 电脑发 `$STOP*..` | 1 秒内停车并回 `$P,...,1` | 串口接线/波特率/中断回调 |
| 5 | 发 `$GOTO` 到场地另一侧 | 能走到位并停稳（±25mm） | 调 `PID_KP/PID_KI`、`MAX_SPEED_MM_S` |

**第 2、3 步是整个固件的地基**：里程计不准，上位机给的"去某个点"就全是错的，
视觉再准也没用。

## 必改参数（`config.h`）

```c
#define WHEEL_DIA_MM      65.0f     // 卡尺量
#define TRACK_MM         180.0f     // 两驱动轮中心距
#define ENCODER_PPR       11.0f     // 查电机手册（常见 11 / 13 / 500 线）
#define GEAR_RATIO        30.0f     // 减速比
#define ENC_MULT           4.0f     // 定时器编码器模式一般 4 倍频
#define MAX_SPEED_MM_S    1200.0f   // 实测能稳跑的速度，别照抄
```

## 常见坑

1. **编码器符号与电机符号不一致** → 速度环正反馈，车会疯转。第 1、3 步必须测。
2. **`ENC_MULT` 用错**（2 倍频/4 倍频搞混）→ 里程计差一倍，看起来"车走 2m 只有 1m"。
3. **`printf("%f")` 在 newlib-nano 下不输出** → 所以本骨架手写了整数格式化，别改回 `%f`。
4. **1kHz 中断里打印/长耗时操作** → 直接拖垮控制环。中断里只做计数和 PID。
5. **UART 溢出后不重启接收** → 之后再也收不到指令（已在 `HAL_UART_ErrorCallback` 里处理）。
6. **推板动作要"算完成"**：`$BLADE` 有动作时间（`BLADE_DOWN_MS`），时间到才回 done，
   否则上位机会在推板还没落下去时就开走。

## 和上位机联调

1. 先把 `strategy/commands.py` 的编码结果在电脑上打印出来，对照协议表逐条核对；
2. 用串口助手手动发 `$STOP*..`、`$GOTO,1000,800,0*..`，确认板子能执行；
3. 打开上位机的实时程序，**先不接决策**，只把 `$P` 位姿解析出来显示，确认坐标一致；
4. 最后才把 `strategy/fsm.py` 的输出接到串口（这一步等于把 `sim.py` 里的
   `SimChassis` 换成真正的串口发送）。
